# Занятие 1. Старт спринта: проблемы студентов

Список из 8 проблем:

- Студенты забывают сроки сдачи домашних заданий.

- Расписание занятий меняется, а актуальная информация теряется в чатах.

- Сложно быстро найти конспект по нужной теме.

- Студенты не знают, где искать информацию о мероприятиях колледжа.

- Потерянные вещи трудно вернуть владельцу.

- Трудно найти напарника для учебного проекта.

- Несколько учебных задач накладываются на один день.

- Студенты забывают о подготовке к контрольным работам.

## Сравнение трёх идей (оценка 1–5)

| **Идея** | **Важность** | **Частота** | **Простота решения** | **Сумма** |
| - | - | - | - | - |
| Планировщик дедлайнов | 5 | 5 | 5 | 15 |
| Каталог конспектов | 4 | 4 | 3 | 11 |
| Афиша колледжа | 3 | 3 | 4 | 10 |

Выбрана проблема: студенты забывают о сроках сдачи учебных работ. Она часто возникает, влияет на успеваемость и может быть решена небольшим приложением.

Питч: «У студентов есть проблема: сроки сдачи заданий разбросаны по разным источникам, поэтому о них легко забыть. Мы хотим помочь студентам собирать все дедлайны в одном списке и отмечать выполненные задачи».

Три варианта решения: 1) бумажный календарь — просто, но неудобно редактировать; 2) таблица — легко создать, но слабая интерактивность; 3) веб-планировщик «Дедлайнер» — удобный список с отметкой выполнения, средняя сложность. Выбран вариант 3.

Целевая аудитория: студенты колледжа; пользуются продуктом при получении нового задания и ежедневно при проверке списка дел.

# Занятие 7. Git: ветки и параллельная работа

# Занятие 8. Git: объединение и конфликт

Причина конфликта: ветки main и feature/about изменили одну и ту же строку README разным текстом. Git не смог выбрать вариант автоматически.

Разрешение: сохранён объединённый вариант: «Дедлайнер помогает студентам планировать учебные задания и контролировать сроки сдачи». Маркеры конфликта удалены.

Команды: git merge feature/about; исправить файл; git add README.md; git commit -m "merge: разрешён конфликт в README".

Проверка: поиск маркеров \<\<\<\<\<\<\<, ======= и \>\>\>\>\>\>\> не находит совпадений. Итоговая формулировка сохраняет смысл обоих вариантов.

- git status — рабочая папка чистая после фиксации изменений.

- git log --oneline — сообщения коммитов описывают конкретные изменения.

- Удалены временные файлы и дубли; пароли и личные данные в репозиторий не добавлялись.

- README содержит назначение, функции, состав команды и запуск через index.html.

- Взаимная проверка: замечание 1 — добавить точную инструкцию запуска; исправлено. Замечание 2 —уточнить, какие функции входят в MVP; исправлено.

Готовность проекта: 35%. Следующий этап: реализовать и проверить основные пользовательские сценарии.

# Занятие 10. Заявка на изменение — Pull Request

Название: Добавление формы создания задания.

Автор: разработчик. Ревьюер: участник другой команды.

Цель: дать пользователю возможность записывать новый дедлайн.

- Изменён файл index.html: добавлены поля названия, предмета и даты.

- Изменён файл js/app.js: добавлена проверка обязательных полей и обработчик отправки формы.

- Способ проверки: заполнить все поля и нажать «Добавить»; новая задача должна появиться в списке.

- Чек-лист ревью: задача соответствует требованию; названия понятны; пустое название отклоняется;существующий список не ломается.

Решение ревьюера: принять после исправления сообщения для пустого поля. В автономном режиме оформляется документ-заявка; это имитация процедуры проверки, а не удалённый Pull Request.

# Занятие 12. Заказчик изменил требования

Карточка изменения: заказчик просит добавить фильтр по предмету.

Польза: студент быстрее находит задания по конкретной дисциплине. Сложность: средняя. Риск: фильтр может конфликтовать с фильтром статуса. Влияние: потребуется дополнительное поле и проверка сочетания фильтров.

Решение: перенести фильтр по предмету в следующую версию. В текущем MVP оставить обязательные сценарии добавления, просмотра и отметки выполнения. Причина — сохранить сроки и проверить базовую работоспособность.

Обновление backlog: T11 «Добавить фильтр по предмету» — Should have, оценка 3, версия 1.1.
